# EV-Option Grid — цифровой двойник ЗИЛ / Даниловский

Интерактивный 3D-прототип системы поддержки инвестиционных решений по развитию сети электрозарядных станций (ЭЗС).
Проект для Международных транспортных проектных соревнований, Проблема № 03 — «Зарядка электромобилей в мегаполисах»
(заказчик — ООО «Росатом Сеть зарядных станций»).

> Это не карта зарядок. Система связывает **транспортный спрос → загрузку ЭЗС → ограничения электросети → инвестиционные варианты →
> экономику и риск → последовательный план развития**. Она отвечает не «где поставить ЭЗС», а «где, когда и какой шаг сделать».

## Запуск

Сборка не нужна: чистые ES-модули, three.js лежит локально (`vendor/`), шрифты — локально (`fonts/`). Нужен любой из вариантов:

```bash
python3 serve.py            # http://localhost:5173  (есть в macOS/Linux; на Windows — py serve.py)
npm run dev                 # если установлен Node.js (npm install не нужен — зависимостей нет)
./start.command             # macOS: двойной клик, откроет браузер
```

`http://localhost:5173/?nodemo` — пропустить вводный пролёт. Открывать по `file://` нельзя (ES-модули) — только через сервер.
Рекомендуется Chrome/Edge/Safari с WebGL2 и дискретной или современной встроенной графикой.

## Что внутри

| Слой | Что делает |
|---|---|
| **Территория** | Реальные данные OpenStreetMap (ODbL): 4 000 зданий, 6 000 участков улиц, Москва-река, МЦК, ж/д, ТЭЦ-9 с трубами, парки, мосты и эстакады ТТК. Стилизованная, не инженерная GIS-модель. |
| **ЭЗС** | 6 адресов-ориентиров (1-й Автозаводский пр., 5 · Автозаводская, 5 и 7 · 1-й Кожуховский пр. · Восточная · Мытная). Каждая — 3D-станция: навес, посты, автомобили, очередь, световая колонна и кольцо загрузки. |
| **Спрос** | 5 типов пользователей (частные EV, такси, корпоративный транспорт, электробусы, коммунальная техника). Потоки маршрутизируются по реальному уличному графу OSM. |
| **Энергосистема** | Режим GRID: земля становится прозрачной, видны подземные узлы (привязаны к реальным подстанциям OSM), кабели с бегущими импульсами, столбики допустимой и желаемой мощности, `GRID CONSTRAINT`. |
| **Опции** | 8 инвестиционных вариантов — у каждого своя 3D-форма: расширение, накопитель, трансформаторный двор, солнечный навес, подготовленная площадка, пилот, новая станция. |
| **Модель** | Сценарный движок: спрос → ёмкость → очередь → допустимая мощность узла → переток спроса между станциями; экономика (CAPEX/OPEX/NPV/IRR/окупаемость); подбор пакета по «реальным опционам» и минимизации сожаления. |
| **Время** | Шкала 2026 · 2027 · 2030 · 2035: решение 2027 года меняет сеть 2030 и 2035. |
| **Сценарии** | Низкий рост EV · Базовый · Высокий рост EV. |

## Управление

* **Мышь**: ЛКМ — вращение, ПКМ/Shift+ЛКМ — панорама, колесо — зум к курсору. Клик по ЭЗС, подстанции, площадке, потоку или варианту.
* **Клавиши**: `1`–`5` — слои CITY / DEMAND / GRID / INVESTMENT / FUTURE, `6` — WALK MODE, `,` `.` — год назад/вперёд.
* **WALK MODE** — `WASD` движение, мышь — обзор, `Shift` — бег, `Space` — прыжок, `E` — взаимодействие, `Q` — под землю (в GRID), `T` — телепорт, `Esc` — выход. Есть коллизии со зданиями и водой.
* «Сценарий защиты» (левая колонка) — чек-лист из 15 шагов, отмечается автоматически и умеет выполнять шаги сам.

## Честность данных

Все значения помечены: **OSM** (реальные объекты), **Адрес-ориентир** (задан командой), **Сценарное допущение** и **Демо-значения MVP**.
Загрузка ЭЗС, мощности и резервы узлов, спрос, CAPEX/OPEX/NPV/IRR — демонстрационные и **не являются** данными РСЗС или
инженерными данными. Прединвестиционная сценарная модель выявляет варианты развития и передаёт их на последующую инженерную проверку;
физический режим электросети Москвы не моделируется. Подробнее — раздел «Данные и допущения» в приложении.
